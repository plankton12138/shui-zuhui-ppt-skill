# 叙事与文案规范：怎么把论文讲成一条线

这份文件决定 PPT 的"含金量"。版式只是壳，壳里的叙事才是听众记住的东西。

## 一句话原则

**每一页都在回答上一页留下的问题。**

```
这是什么问题 → 现在的方法为什么不行 → 所以他们怎么做的 → 怎么证明有效 → 还有什么没解决
```

写每一页之前先问自己：这一页如果删掉，故事会不会断？不会断就删掉。

## 页标题 = 该页的论断

不要写"研究方法""实验结果"这种栏目名。标题要直接给出结论，让听众扫一眼就知道这页的立场：

| ❌ 栏目名 | ✅ 论断 |
|----------|---------|
| 研究方法 | 研究方法（一）：总体架构 |
| 实验结果 | 实验结果（一）：部署开销由资源类型决定 |
| 实验结果 | 实验结果（二）：SLO 闭环快，开销几乎为零 |
| 结论 | 结论与不足 |

方法页可以中性（因为要讲结构），**实验页必须是论断**。

## 第 2 页：研究背景

四段式，不要写成综述：

1. **背景** —— 大趋势一句话（IoT/实时应用把计算推向边缘）
2. **特点** —— 为什么难：异构的三个维度（硬件、平台、网络）
3. **目标** —— 作者想让什么东西变成一次调用
4. **两个挑战** —— 直接对应后面方法的两块设计

红字放在"目标"和"挑战"上，因为那是全文的钩子。

反面教材：花半页解释什么是边缘计算。听众都是同行，不需要。

## 第 3 页：研究现状

这一页是"看起来读得深"的关键。结构固定：

```
路线 A：代表工作 1、代表工作 2 → 红字：缺陷
路线 B：代表工作 1、代表工作 2 → 红字：缺陷
路线 C：代表工作 1…3          → 红字：缺陷
────────────────────────────────
共同局限：……（红字收尾，就是本文的立题点）
```

三条硬要求：

- **每条路线必须落到一句缺陷**，缺陷要具体（"不处理 SLO 违约""不支持 serverless"），不要写"仍有提升空间"
- **不要罗列所有 related work**，每条路线 2–3 个足够，剩下的放口播里
- **共同局限要能直接推出本文方法**——写不出这句，说明你还没读懂这篇论文的定位

## 第 4–5 页：研究方法

分两页：**结构** + **动机**。

第 4 页（配架构图）只讲"有哪些部件、怎么连起来"，按层讲，每层一句。不要在这一页解释算法。

第 5 页讲"为什么这么设计"，用编号 ①②③④，每一条对应第 2 页提出的一个障碍：

```
① 统一抽象  ← 解决"平台异构"
② 部署提速  ← 解决"部署太慢"
③ 指标补齐  ← 解决"监控看不到"
④ SLO 闭环  ← 解决"谁来守"
```

这种一一对应关系，是"研究很深"最直接的证据。听众会自己把线连起来。

**不要**在这一页抄公式、列符号表、解释超参数。真要讲，放口播里说一句"具体阈值在论文第 X 节"。

## 第 6 页：实验设置

一页说清四件事，能配测试床表就配表：

- 测试床：几台机器、什么规格、在哪
- 负载：跑的是什么（越简单越要说清"为什么简单"）
- 指标：测了什么
- 场景：几组实验，每组验证什么

红字只标"场景编号"或"指标名"，不要标数字。

## 第 7–8 页：实验结果

**图 + 数字 + 一句机理**。三段式：

```
现象：EC2 启动 ~200 s，比 OpenFaaS 慢一个量级
机理：要现装 OpenFaaS 与 Node Exporter
含义：跨层部署的瓶颈在基础设施准备，不在调度
```

只写现象不写机理 = 念图；只写机理不写数字 = 空谈。两个都要。

红字标**数字**和**反直觉的结论**，不标"显著提升"这种空话。

补充结果页（开销、鲁棒性）可以压到 2–3 条，因为它的作用是"堵住审稿人的嘴"，不是主线。

## 第 9 页：结论与不足

左栏结论 3 条，右栏不足 4–5 条。

不足怎么写才显得懂行：

1. **作者自己承认的**（论文 limitations / future work 段落里）
2. **数据能推出来的**（规模只有 13 个资源、只测了时延类 SLO）
3. **你自己加的评估视角**（基线只有 Python client、没做多租户、没量化重调度期间的中断）

第 3 类最能加分，但要克制——说"如果我来做会先补什么"，而不是"这篇论文很水"。

## 强调色规则（红为主，蓝为辅）

| 该强调 | 不该强调 |
|------|--------|
| 缺陷、gap | 作者名、机构名 |
| 机制名（预拉取、Event Bus） | 泛泛的形容词 |
| 关键数字（200 s、0–5 s、13 个资源） | 年份、卷期号 |
| 反直觉结论（"开销几乎为零"） | 常识性表述 |

红色是默认强调色（缺陷、机制、关键数字）。当需要把**两类同类信息分开**时才引入蓝字——例如"缺陷（红）vs 该路线的优势（蓝）"、"本文方法（红）vs 对照基线（蓝）"。没有区分需求就全部用红，不要为了好看加蓝。

密度：**每页红+蓝合计 1–3 处**。一页全是强调色等于没有重点。

## 长度控制

- 一条 bullet ≤ 45 字，超过就拆成两条或删掉修饰语
- 一页 ≤ 6 条 bullet
- 一页 ≤ 3 个数字
- 页数以讲清为准，通常 8–12 页；每超出一页都要能回答"这页删掉故事会断吗"

写完之后做一次"删一半"测试：随便挑一页，把每条 bullet 的后半句删掉，如果意思没变，那后半句本来就该删。

## 不要做的事

- 不要把摘要翻译一遍当背景页
- 不要按论文章节顺序排（Introduction / Related Work / Method / Evaluation 是写给审稿人的，不是讲给组会的）
- 不要出现"本文将详细介绍"这种过渡句
- 不要在 PPT 上写"谢谢""请批评指正"
