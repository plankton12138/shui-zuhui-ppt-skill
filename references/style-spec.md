# 版式规范与 deck.json 字段说明

`build_deck.py` 只认这一份规范。想改版式就改脚本里的常量，不要靠 PPT 里手调。

## 画布与网格

| 项 | 值 |
|----|-----|
| 画布 | 16:9，13.333 × 7.5 in（EMU 12192000 × 6858000） |
| 左外边距 | 0.92 in |
| 右外边距 | 0.40 in（正文最大宽度 12.01 in） |
| 标题基线区 | top 0.50 in，高 0.95 in |
| 正文区 | top 1.72 in → bottom 7.02 in（可用高 5.30 in） |
| 图版区 | left 0.28 in，宽 8.10–8.40 in（`figure` 类型） |
| 图侧文字 | 宽 3.95–4.05 in |

## 字号

| 用途 | 字号 | 说明 |
|------|------|------|
| 封面主标题 | 38pt | 长标题自动按比例缩，但不小于 28 |
| 页标题 | 40pt | 超过一行宽自动降到 38/36/…/26，保证单行 |
| 导语（`lead`） | 30–34pt | 一页最多一句，用于把听众拽进这一页 |
| 正文 | 24pt | 首选。装不下才 22/20/18 |
| 图侧/栏内文字 | 17–20pt | 图占地方，只能让字让步 |
| 图注 | 11pt，灰 `#595959` | 居中，紧贴图片下沿 0.04 in |
| 下限 | 14pt | 低于 14 说明该删字，不该继续缩 |

`fit_size()` 会按"字宽估算 → 行数 → 行高"逐级试字号，装得下就用最大的。它只是估算，
**交付前必须渲图肉眼确认**。

## 颜色

基调是白底黑字，强调色克制。默认只用前两种；`BLUE` 是可选的第二强调色，确实需要区分两类同类信息（如"缺陷 vs 优势""本文 vs 对照"）时才用。黑灰之外**全篇不超过两种强调色**：

```
BLACK #000000   正文、标题
RED   #FF0000   默认强调色（缺陷、机制、关键数字，每页合计 ≤ 3 处）
BLUE  #0070C0   可选第二强调色（与红区分的同类强调），行内标记 <b>/<bb>
GREY  #595959   图注
```

## 字体

中文 `等线`，西文 `等线`（同族，保证中英混排字重一致）。
`style_run()` 同时写 `a:latin` 和 `a:ea`，否则中文会掉回主题字体。

## 项目符号

`•` + 悬挂缩进 26pt（`marL=26pt, indent=-26pt`）。导语与正文用同一个缩进量，
否则两段圆点不在一条竖线上——这是最容易露怯的细节。

## deck.json 结构

顶层：

```json
{
  "title_en": "论文英文全名（封面用《》包住）",
  "title_zh": "中文题眼，一句话，可带冒号解释",
  "venue": "arXiv:2411.16697 [cs.DC] · 2024.11",
  "authors": "第一作者 等 · 单位（可选，14pt 灰）",
  "slides": [ ... ]
}
```

`slides[]` 支持 6 种 `type`。

### 1. `cover`

无字段，直接取顶层的 `title_en` / `title_zh` / `venue` / `authors`。
版面：venue 右上角 14pt；标题居中 38pt；中文副题居中 24pt。

### 2. `points` — 纯文字页（背景、方法要点）

```json
{
  "type": "points",
  "title": "研究背景",
  "lead": "从云到端：<r>计算连续体</r>（Computing Continuum）",
  "lead_size": 32,
  "size": 23,
  "bullets": ["**背景**：……", "**目标**：……<r>按 SLO 选资源</r>"]
}
```

- `lead`：可选。放在正文上方的一句大字，带圆点，与正文左对齐。
- `size`：可选，正文字号上限（脚本只会往下缩，不会往上顶）。
- `bullets`：4–6 条为宜，单条控制在 45 字以内。

### 3. `columns` — 多栏对照（研究现状）

```json
{
  "type": "columns",
  "title": "研究现状",
  "size": 18,
  "columns": [
    {"head": "云侧资源管理器", "lines": ["Xioadi 等[6]：……"], "tail": "缺陷：……"}
  ],
  "footer": "**共同局限**：……<r>异构平台的优势用不上</r>",
  "footer_size": 21
}
```

- 栏数 2–3，等宽自动分配（3 栏每栏 3.57 in）。
- `tail`：该栏的判词，默认整段染红（tail 里若已有行内标记则尊重标记，不再强制染色），前面自动留 10pt 间距。
- `footer`：横贯全页的一句总结，位置跟随最高的一栏（`max_end + 0.30`），不钉死在页底。
- 三栏时正文 17–18pt 是常态，**不要**为了放大字号删掉代表工作。

### 4. `figure` — 一张图 + 侧栏文字（架构图、宽表）

```json
{
  "type": "figure",
  "title": "研究方法（一）：总体架构",
  "image": "figs/fig1_arch.png",
  "side": "right",
  "img_w": 8.35,
  "text_w": 3.95,
  "size": 19,
  "caption": "Fig. 1  架构设计（原论文）",
  "bullets": ["**定位**：……"]
}
```

- `side`：文字在图的哪一侧（图在另一侧）。
- 图片等比缩放并居中放进图版区；图注贴在图的实际下沿，不贴页底。
- 侧栏文字 4–5 条，每条 30 字以内。

### 5. `figure_stack` — 两张图上下叠放 + 侧栏文字

```json
{
  "type": "figure_stack",
  "img_w": 7.55,
  "text_w": 4.15,
  "size": 18,
  "images": [{"path": "figs/fig2.png", "caption": "Fig. 2  ……"}, {"path": "figs/fig4.png", "caption": "Fig. 4  ……"}],
  "bullets": ["……"]
}
```

用于"主结果 + 资源开销"这类同一 scenario 的两张图。两张图共享左栏宽度，纵向均分。

### 6. `figure_pair` — 两张图并排 + 下方文字

```json
{
  "type": "figure_pair",
  "img_h": 2.95,
  "size": 21,
  "images": [{"path": "figs/fig5.png", "caption": "……"}, {"path": "figs/fig6.png", "caption": "……"}],
  "bullets": ["……"]
}
```

图按高度对齐（`img_h`），宽度各自等比。下方文字限宽 11.5 in，最多 3 条。

### 7. `two_col` — 结论与不足

```json
{
  "type": "two_col",
  "title": "结论与不足",
  "size": 19,
  "left": {"head": "结论", "bullets": ["……"]},
  "right": {"head": "不足", "bullets": ["……"]}
}
```

左 3 条结论、右 4–5 条不足。右栏通常更挤，脚本会为两栏分别挑字号。

## 行内标记

| 写法 | 效果 | 用在哪 |
|------|------|--------|
| `**文本**` | 加粗黑 | 条目前的小标签（`**背景**：`）、术语 |
| `<r>文本</r>` | 红 | 缺陷、机制、关键数字（默认强调色） |
| `<rb>文本</rb>` | 红 + 粗 | 需要同时强调的极少数情况 |
| `<b>文本</b>` | 蓝 | 第二强调色：与红区分的同类信息（如优势、对照项），可选用 |
| `<bb>文本</bb>` | 蓝 + 粗 | 同上，需要加粗时 |

一段文字里可以有多个标记，但**同一句不要强调两次以上**；每页红+蓝合计不超过 3 处。

## 排版禁忌

1. 标题折行（会压到正文区）——脚本会缩字号，仍折行就改短标题
2. 图注飘在页底而图在上方——`figure` 类型已修正，新增类型要照做
3. 图里带页眉/英文原图注——裁图阶段解决，别指望排版补救
4. 一页三种以上字号层级
5. 用 `size` 硬顶大字号导致溢出——`fit_size` 会救，但救出来的是 14pt，等于没救
